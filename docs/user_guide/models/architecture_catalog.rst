Architecture Catalog
====================

Enerzyme supports several internal architectures and external wrappers. Choose based on targets (energy/forces only vs charge/dipole), system size, equivariance needs, and optional dependencies.

The public YAML name selects a factory in :code:`enerzyme.models.presets`.
Use :code:`available_architectures()` to list canonical names and
:code:`get_architecture(name)` to resolve an alias. The factory combines
an embedding, message-passing blocks, and a head. Architecture packages
contain their default pipeline parameters and specialized operations.
See :doc:`/developer_guide` for a complete preset construction example.

For presets with e3nn layers, set :code:`e3nn_codegen: fx` in :code:`build_params`
to keep generated tensor products and linear maps as FX graphs.
This lets :code:`torch.compile(model)` trace their weight and coordinate
derivatives when training on forces. The option applies to configured
readouts as well as the Core. Both representations use the same checkpoint
keys. NequIP and Allegro use their original scripted tensor operations in
eager execution and expose those same operations to :code:`torch.compile`
under their default settings. Other presets keep their usual code generator.

On PyTorch 2.13, ordinary CPU Inductor uses scalar C++ kernels for force
training with CACE, CAMP, GRACE, EquiformerV3, and the EquFlashV2 and Nequix
FX configurations. The setting applies to each model call. Equiformer with
FX kernels and DPA4 in float64 use native derivatives for CPU force training
to preserve their energies, forces and weight gradients. Details and
per-preset validation results are in the :doc:`/developer_guide`.

External models are declared under :code:`Modelhub.external_FFs` with the same :code:`active` / :code:`layers` pattern where supported.

**DimeNet** (:code:`architecture: dimenet`) is a native port of Gasteiger et al. (ICLR 2020, arXiv:2003.03123) under :code:`enerzyme/models/dimenet/`, following `gasteigerjo/dimenet <https://github.com/gasteigerjo/dimenet>`_ (MIT) **original DimeNet** (bilinear spherical Fourier–Bessel interaction — **not** DimeNet++). Shared pieces: :code:`DimeNetEnvelope` in :code:`enerzyme/models/mp/basis/envelope.py`, :code:`BesselRBF` with :code:`flavor: dimenet` (trainable frequencies × ``u(x)/x``), and :code:`HierachicalReadout` with :code:`head_type: mlp` for the paper output MLPs. The Core owns embedding-block messages, directional MP, SBF, and RBF-gated atom scatter; it emits hierarchical :code:`atom_feature` ``(N, F, num_blocks+1)``. Default stacks use :code:`HierachicalReadout` + :code:`EnergyReduce` + :code:`Force`. Angles use the paper / DimeNet++ convention at atom ``j`` (not the official TF pretrained bug at atom ``i``). Example: :code:`enerzyme/config/dimenet_layers_example.yaml`. Tests: :code:`test/test_dimenet_ops.py`, :code:`test/test_dimenet_core.py`, :code:`test/test_dimenet_parity_ops.py` (PyG original DimeNet). Enerzymette only needs :code:`architecture: dimenet` plus a resolved :code:`config.yaml`.

**DimeNet++** (:code:`architecture: dimenet++` or :code:`dimenetpp`) is the fast variant from the same repository (arXiv:2011.14115). It reuses the DimeNet triplets, spherical basis, embedding block, residual layers, Bessel flavor, and :code:`HierachicalReadout`. The Core replaces the bilinear tensor with Hadamard products plus a down/up bottleneck (:code:`int_emb_size`, :code:`basis_emb_size`) and a bias-free projection to :code:`out_emb_size`, so :code:`atom_feature` is ``(N, out_emb_size, num_blocks+1)`` and the readout MLP runs at that width (:code:`num_hidden_layers: 3` matches the paper output block after the projection). Defaults follow ``config_pp.yaml`` (4 blocks, emb 128, out 256, int 64, basis 8, 7 spherical, 6 radial, cutoff 5). The radial filter and Swish down-projection run on every edge (so the gathered source message still sees ``d_kj``); the spherical basis is applied after the triplet gather. Example: :code:`enerzyme/config/dimenetpp_layers_example.yaml`. Tests: :code:`test/test_dimenetpp_core.py`, :code:`test/test_dimenetpp_parity_ops.py`. Enerzymette only needs :code:`architecture: dimenet++` in the resolved :code:`config.yaml`.

**M3GNet** (:code:`architecture: m3gnet`) is an implementation of Chen and Ong (Nat. Comput. Sci. 2022, `doi:10.1038/s43588-022-00349-3 <https://doi.org/10.1038/s43588-022-00349-3>`_) under :code:`enerzyme/models/m3gnet/`, following the update rules in `materialyzeai/matgl <https://github.com/materialyzeai/matgl>`_ (BSD). matgl is not imported, and its checkpoints do not load. The Core is the three-body bond update plus the gated graph convolution. It reads :code:`RandomAtomEmbedding` and :code:`SphericalBesselRBF` (``j_l(z_{ln} r / c)`` with the ``c^{-3/2}`` normalizer, no envelope on the basis; ``l = 0`` is the usual ``sqrt(2/c) sin(nπr/c) / r``). Triplets are two edges that share the receiver, including distinct periodic images of one neighbor. :code:`threebody_cutoff` (default 4 Å) is a polynomial envelope of order 3 inside the Core. The neighbor list stays at :code:`cutoff_sr` (default 5 Å) and must be at least that long. Each block adds a bias-free gated map of ``Y_l^0`` onto the bond, then a gated MLP of ``(v_i, v_j, e_ij)`` weighted by a bias-free linear map of the radial basis. Messages accumulate on the receiver. The latent is the final :code:`atom_feature` ``(N, F)`` with ``feature_irreps = "{F}x0e"``. The potential head is :code:`SimpleReadout` with :code:`head_type: gated` (sigmoid gate, no activation on the last value; hidden width follows Core :code:`units`). Then :code:`EnergyReduce` and :code:`Force`. An isolated atom keeps its species embedding, so that head is a learned elemental baseline. :code:`AtomicAffine` can add another reference. Global state, the azimuthal angle ``φ``, and the smooth Bessel option are not part of this potential. :class:`~enerzyme.models.mp.nn.mlp.GatedMLP` is shared. Example: :code:`enerzyme/config/m3gnet_layers_example.yaml`. Tests: :code:`test/test_m3gnet_ops.py`, :code:`test/test_m3gnet_core.py`. Enerzymette only needs :code:`architecture: m3gnet` plus a resolved :code:`config.yaml`.

**MatterSim** (:code:`architecture: mattersim`, also :code:`m3gnet-graphormer` and :code:`m3gnet_graphormer`) is Yang et al. (arXiv:2405.04967) under :code:`enerzyme/models/mattersim/`. The public `microsoft/mattersim <https://github.com/microsoft/mattersim>`_ package releases the M3GNet potential used for zero-shot simulation. Its Graphormer branches raise ``NotImplementedError``, and the v1 checkpoints do not load here. This preset shares the M3GNet triplet updates and adds the structural encoder from supplementary section S1.3. Pre-core layers are :code:`SphericalBesselRBF`, :code:`GaussianRBF` (``flavor: SchNet``, ``apply_cutoff_fn: false``), and :code:`RandomAtomEmbedding`. The Core renames the Gaussian field to ``graphormer_rbf``. Centrality adds :code:`Σ_j Linear(m_ij Φ_ij)` to the receiver. Each attention block adds :code:`Linear(Φ_ij)` to the logits and multiplies the softmax weights by the order-3 polynomial mask. ``idx_j`` is the in-cell atom, so a periodic image reuses that atom's key and value. ``attention_cutoff`` cannot exceed ``cutoff_sr``. ``num_attn_layers: 0`` and ``use_centrality: false`` reproduces M3GNet. The latent is flat :code:`atom_feature`. Energy uses :code:`SimpleReadout` (``head_type: gated``) → :code:`EnergyReduce` → :code:`Force`. The paper's GeoMFormer direct-force decoder and lattice stress head are separate from this conservative potential. The checked-in widths are a small stack (2 attention layers, 4 heads, 16 Gaussians). The published encoder (24 layers, 32 heads, hidden 768, 128 Gaussians, 20 Å neighbor list, 5 Å mask) is the same Core. Example: :code:`enerzyme/config/mattersim_layers_example.yaml`. Tests: :code:`test/test_mattersim_ops.py`, :code:`test/test_mattersim_core.py`. Enerzymette only needs :code:`architecture: mattersim` plus a resolved :code:`config.yaml`.

**CHGNet** (:code:`architecture: chgnet`) is Deng et al. (Nat. Mach. Intell. 2023, `doi:10.1038/s42256-023-00716-3 <https://doi.org/10.1038/s42256-023-00716-3>`_) under :code:`enerzyme/models/chgnet/`. The message passing follows `CederGroupHub/chgnet <https://github.com/CederGroupHub/chgnet>`_. That package is not imported, and its checkpoints do not load. The Core reads :code:`RandomAtomEmbedding` and two :code:`BesselRBF` layers with ``flavor: gemnet`` (``u_p(r) · √(2/c) · sin(nπr/c) / r``). One basis uses the atom-graph cutoff (default 5 Å). The other uses ``bond_cutoff`` (default 3 Å); the Core renames its field to ``rbf_bg``. Directed edges must come in reverse pairs, including the opposite periodic image. They share one bond state. Angles are the M3GNet receiver triplets inside ``bond_cutoff``, with the reference rule that an edge exactly at the cutoff can be updated and cannot be the other leg. The Fourier expansion of the angle (sine channels, then cosine) is inside the Core. Each block is a gated message on atoms, then bonds, then angles. The gated MLP is the shared :class:`~enerzyme.models.mp.nn.mlp.GatedMLP` with ``norm: layer`` before the final SiLU and sigmoid. The last block updates atoms only. ``atom_feature_charge`` is the state before that update. ``atom_feature`` is the state after it and after the readout layer norm. Both are ``(N, F)`` with ``feature_irreps = "{F}x0e"``. :code:`AbsoluteLinearReadout` maps the charge latent to the nonnegative magnitude :code:`Ma`. :code:`SimpleReadout` (``head_type: mlp``, two SiLU hidden layers) maps the final latent to site energies. Then :code:`EnergyReduce` and :code:`Force`. The energy is extensive. The paper's per-atom energy target is a data normalization, applied after the force derivative in the reference code. Stress with respect to lattice strain is not a layer here. Elemental references belong in the atomic-energy transform or :code:`AtomicAffine`. The checked-in widths are the paper's (9 radial, 9 angular, envelope order 5). CHGNet 0.3.0 is the same Core with a 6 Å atom graph, 31 radial functions, 31 angular functions, and envelope order 8. Set ``gmlp_norm: null`` and ``readout_norm: null`` to drop the reference layer norms. Example: :code:`enerzyme/config/chgnet_layers_example.yaml`. Tests: :code:`test/test_chgnet_ops.py`, :code:`test/test_chgnet_core.py`. Enerzymette only needs :code:`architecture: chgnet` plus a resolved :code:`config.yaml`.

**ALIGNN** (:code:`architecture: alignn`) is Choudhary and DeCost (npj Comput. Mater. 2021, `doi:10.1038/s41524-021-00650-1 <https://doi.org/10.1038/s41524-021-00650-1>`_) under :code:`enerzyme/models/alignn/`. The update follows `usnistgov/alignn <https://github.com/usnistgov/alignn>`_, including the atomwise force field. That package is not imported, and its checkpoints do not load. The distance expansion is :code:`GaussianRBF` with ``flavor: alignn``: ``exp(-(r-μ)² / Δ)``, ``Δ = cutoff / (num_rbf - 1)``, no envelope. That is not the SchNet width ``1/(2Δ²)``. The angle expansion uses the same Gaussian on the cosine in ``[-1, 1]`` and stays inside the Core, because the angles are edges of the directed line graph. That line graph is a head-to-tail path ``a -> b -> c``. It is not the receiver-triplet graph used by M3GNet, CHGNet, and DPA3. ``idx_i`` is the destination and ``idx_j`` is the source. ``backtracking`` keeps a bond paired with its reverse, which is the released default; the cosine of that pair is ``+1``. The convolution is the released edge-gated layer: the gate is a sigmoid of the edge message, normalized per feature channel. A destination with one incoming edge drops that edge feature, because the gate cancels. ``update_order: code`` runs the atom graph before the line graph inside each ALIGNN layer, so that layer's atom state does not yet contain the angle. A following gated convolution reads the updated bond when it is one of several incoming edges. ``update_order: paper`` follows equations (7) and (8) and runs the line graph first. Equal initial bond features make that first line-graph update independent of the angle; the next layer carries it after the atom graph has split the bonds. The default stack is ALIGNN-FF: 2 ALIGNN layers, 2 gated convolutions, width 64, 80 bond Gaussians, 40 angle Gaussians, LayerNorm, cutoff 8 Å. ``PUBLISHED_PROPERTY_CORE_PARAMS`` is the 2021 property model (4 + 4 layers, hidden 256, batch norm). The species table is :code:`RandomAtomEmbedding`, not the CGCNN elemental vector and not the raw atomic number. The Core still applies the released Linear-Norm-SiLU on that vector and on the bond and angle bases. :code:`SimpleReadout` with ``head_type: dense`` is one linear map. Summing it is the released average-pool times the atom count, including the bias. Then :code:`EnergyReduce` and :code:`Force`. ``multiply_envelope`` multiplies only the initial bond embedding by :func:`enerzyme.models.cutoff.polynomial_envelope`. Later messages are not forced to zero at the cutoff. The reference short-bond hinge is not in the stack; a pair wall is :code:`ZBLRepulsionEnergy` or :code:`ScreenedZBLRepulsionEnergy`. The latent is ``atom_feature`` ``(N, F)`` with ``feature_irreps = "{F}x0e"``. Example: :code:`enerzyme/config/alignn_layers_example.yaml`. Tests: :code:`test/test_alignn_ops.py`, :code:`test/test_alignn_core.py`. Enerzymette only needs :code:`architecture: alignn` plus a resolved :code:`config.yaml`.

**SpinConv** (:code:`architecture: spinconv`) is Shuaibi et al. (arXiv:2106.09575) under :code:`enerzyme/models/spinconv/`. The grid convolution follows `facebookresearch/fairchem <https://github.com/facebookresearch/fairchem/blob/ocp2.0/ocpmodels/models/spinconv.py>`__ on branch ``ocp2.0``. That file is not imported, and its checkpoints do not load. The distance expansion is :code:`GaussianRBF` with ``flavor: spinconv``: ``exp(-½ (r-μ)² / σ²)``, ``σ = basis_width_scalar · Δ``, ``Δ = cutoff / (num_rbf - 1)``, no envelope. The OC20 config sets ``basis_width_scalar`` to 3. The species table is one :code:`RandomAtomEmbedding`. Each mixture block learns its own source and target maps of that vector. The released model stores a separate table in every block. ``idx_i`` is the destination and ``idx_j`` is the source. The sphere is centered on the source. Local ``+x`` is the unit ``vij``, from the destination toward the source. Incoming messages at the source are bilinearly splatted onto a latitude–longitude grid. A circular convolution whose kernel spans the longitude axis, SiLU, and average pooling remove the roll around the bond. GroupNorm uses ``hidden_channels / group_channels`` groups. The first update replaces the distance initialization; later updates add. ``residual_first: true`` adds the first update as well. ``scale_distances`` applies a learned gain and offset for each species pair and evaluates the same Gaussian again. The gain starts at 1. Scattered messages are divided by ``max_num_neighbors / 2 + 1``. A pair is kept when either direction is among the closest ``max_num_neighbors`` at its destination. The latent is ``atom_feature`` ``(N, mid_hidden_channels)`` with ``feature_irreps = "{D}x0e"``, the mixed node state before the energy block's last linear. :code:`SimpleReadout` (``head_type: dense``) is that linear. Then :code:`EnergyReduce` and :code:`Force`. Bilinear weights are constants in the backward pass. The bond partner lies on the pole, where ``asin`` and ``atan2`` have no finite derivative, and the released code drops that Jacobian when ``force_estimator`` is ``grad``. Positions still enter the force through the distances and the message values. The force-centric head, which paints three axis-aligned spheres and averages random rotations, is not in this stack. An isolated atom keeps a species-dependent latent and has zero force. The checked-in widths are the OC20 config: 3 updates, hidden 32, mid 256, 512 Gaussians, a 16×12 grid, 40 neighbors, 6 Å. The energy-centric paper grid is 12×8. A degree-1 destination, or a destination whose edges all sit at the cutoff, has no second axis. The normal is then the cross product of the bond with a lab axis, and the frame stays a rotation. A non-degenerate second axis still rotates with the molecule; the released lab-frame ``1e-4`` nudge is not added. Example: :code:`enerzyme/config/spinconv_layers_example.yaml`. **GemNet** (:code:`architecture: gemnet`, :code:`gemnet-t`, or :code:`gemnett` for GemNet-T; :code:`gemnet-q` or :code:`gemnetq` for GemNet-Q) is an original implementation of Gasteiger, Becker, and Günnemann (NeurIPS 2021, arXiv:2106.08903) under :code:`enerzyme/models/gemnet/`. `TUM-DAML/gemnet_pytorch <https://github.com/TUM-DAML/gemnet_pytorch>`_ is Hippocratic License 2.0 and is not vendored; its checkpoints do not load. The Core is the directional interaction stack. It reads :code:`RandomAtomEmbedding` and :code:`BesselRBF` with :code:`flavor: gemnet` (``u_p(r) · √(2/c) · sin(nπr/c) / r``, envelope order ``envelope_exponent``, default 5). That basis is separate from the DimeNet flavor, which uses ``p = exponent + 1`` and ``u(x)/x``. ``basis_cutoff`` is the envelope cutoff and must equal Core :code:`emb_cutoff`. The neighbor list may be longer than that cutoff. Spherical Bessel zeros and the zonal harmonic :math:`Y_l^0` are shared with DimeNet; the triplet graph is not, because a GemNet triplet is two edges that meet at the receiver. GemNet-T (:code:`triplets_only: true`, the default for bare :code:`gemnet`) uses one cutoff. Messages live on edges shorter than :code:`emb_cutoff`. Each block updates an edge from those triplets, adds the symmetric reverse-edge message, and scatters an RBF-gated residual onto the receiver. The atom state inside the block is not the energy latent. The latent is the per-block message scatter, hierarchical :code:`atom_feature` ``(N, F, num_blocks+1)``. GemNet-Q (:code:`triplets_only: false`) adds dihedral quadruplets. :code:`cutoff_sr` and :code:`int_cutoff` cover the central bond (paper default 10 Å). :code:`emb_cutoff` and :code:`basis_cutoff` stay at 5 Å. :code:`int_cutoff` must sit between :code:`emb_cutoff` and :code:`cutoff_sr`. A quadruplet uses four distinct atoms. Angles, including the dihedral, are unsigned and lie in :math:`[0, π]`. Forces are conservative :code:`Fa = -∇E` from the shared :code:`Force` layer. Direct-force GemNet-dT and GemNet-dQ are not implemented. The default head is bias-free :code:`HierachicalReadout` (:code:`head_type: dense`). An isolated atom has zero network energy; elemental references belong in :code:`AtomicAffine`. Variance scales stay at 1. Real spherical harmonics use the standard :math:`l^2 + (m + l)` channel order, which is not the upstream order. Examples: :code:`enerzyme/config/gemnet_layers_example.yaml`, :code:`gemnetq_layers_example.yaml`. Tests: :code:`test/test_gemnet_ops.py`, :code:`test/test_gemnet_core.py`. Enerzymette only needs :code:`architecture: gemnet-t` or :code:`architecture: gemnet-q` in the resolved :code:`config.yaml`.

The published direct-force head and the OC20 tag filter ``qint_tags: [1, 2]`` are not in this stack: every atom can enter a quadruplet. Variance scales stay at 1. The checked-in widths are the OC20 base config (4 blocks, edge width 512, 128 Gaussians, 12 Å, 30 / 8 / 20 / 1000 neighbors). Example: :code:`enerzyme/config/gemnet_oc_layers_example.yaml`. The initial node state is :code:`RandomAtomEmbedding` passed through SiLU (or :code:`silut`). The Core builds the radial gate, the :math:`1/r` edge seed, and the cosine angle seed. :func:`enerzyme.models.cutoff.polynomial_transition` is the DeePMD polynomial gate; :func:`enerzyme.models.cutoff.exponential_switch` is Eq. 12. :func:`enerzyme.models.layers.symmetrize.dp_symmetrize` is the embedding-matrix contraction shared with the Deep Potential descriptor. Messages scatter with :func:`enerzyme.models.functional.reduce_edge`. The latent is invariant :code:`atom_feature` ``(N, n_dim)`` with ``feature_irreps = "{n_dim}x0e"``. :code:`SimpleReadout`, :code:`EnergyReduce`, and :code:`Force` give conservative forces. :code:`AtomicAffine` is the per-element energy bias. A dataset one-hot is a fitting input and is not concatenated inside the Core. Leave ``cutoff_fn`` unset on :code:`RangeSeparation`; ``cutoff_sr`` must be at least ``e_rcut`` (6 Å). ``e_sel`` and ``a_sel`` set the neighbor normalization :math:`N_m`, not a pad length. ``smooth_edge_update: true`` is Eq. 12. Order-3 dihedrals are outside this Core. Example: :code:`enerzyme/config/dpa3_layers_example.yaml`. Tests: :code:`test/test_dpa3_ops.py`, :code:`test/test_dpa3_core.py`. Enerzymette only needs :code:`architecture: dpa3` plus a resolved :code:`config.yaml`.

During CPU force training on PyTorch 2.13, DPA3 compiles its forward and
weight backward with independent reductions at the two edge endpoints.
The default compiler otherwise drops part of the derivative. Normal
:code:`torch.compile(model)` applies the setting for this call. Explicit
full-graph CPU Inductor training requires the compiler option
:code:`{"cpp.max_horizontal_fusion_size": 1}`.
For CPU force inference, the ordinary call also sets :code:`cpp.simdlen` to
1. With both settings, the compiled model returns forces and supports further
coordinate derivatives of the energy.

**DPA4** (:code:`architecture: dpa4`) implements the EMFA SO(2) descriptor of Li et al. (2026, arXiv:2606.02419) under :code:`enerzyme/models/dpa4/` (:code:`interaction.py`, :code:`so2.py`). Shared SO(3) helpers (C³ envelope, Apache e3x Lebedev tables / :code:`S2LebedevProjector`, packed indexing, :code:`FocusSO2Linear`, focus gated activation, degree RMSNorm, Bessel×C³ RBF, quaternion edge frames + shared e3nn/:code:`Jd` Wigner-D via :code:`A R Aᵀ` into DPA4's Cartesian basis; flat :code:`SO3Grid` / Lebedev behind :code:`S2GridProjector`) live in :code:`enerzyme/models/mp/equivariant/`. The Core owns the radial cache, geometric/environment seed, m-truncated interactions, and Lebedev-grid equivariant FFN. It emits :code:`atom_feature` / :code:`atom_sphere_feature`, so the standard :code:`SimpleReadout` + :code:`EnergyReduce` + :code:`Force` stack applies. Example: :code:`enerzyme/config/dpa4_layers_example.yaml`. Tests: :code:`test/test_dpa4_core.py`, :code:`test/test_dpa4_parity_ops.py`. Enerzymette only needs :code:`architecture: dpa4` plus a resolved :code:`config.yaml`.

**DPA4C** (:code:`architecture: dpa4c`) is Li et al. (arXiv:2608.19041) under :code:`enerzyme/models/dpa4c/`. DeePMD-kit is LGPL-3.0 and is not imported; its checkpoints do not load. The Core reads each neighbor shell once. A shared radial map and an ordered-pair scale and shift build the edge amplitude, real Cartesian harmonics carry the angle, and one reduction produces degree-wise moments. Exact channel Grams, a low-rank Cartesian bispectrum, and the projected quartic become the invariant :code:`atom_feature`. The center embedding is the initial feature and is appended again after the two neighborhood masses. ``build`` rejects a ``cutoff_fn`` on :code:`RangeSeparation`; the neighbor list is a hard ball and the Core's C³ envelope (exponent 5) is the only smooth cutoff. Self-loops are rejected. A geometric column whose calibration RMS is at most ``1e-12`` keeps scale 1. :class:`~enerzyme.models.mp.basis.radial.BesselC3RadialBasis` is evaluated without that envelope (``apply_envelope: false``). ``dim_embedding`` must equal ``channels`` and be one of 8, 16, 32, 64, 128. ``lmax`` is 2, 3, or 4. ``radial_modes`` adds shared radial profiles without widening the invariant vector. Grades Nano, Mini, Neo, Air, and Plus are :code:`PUBLISHED_GRADES`. The energy MLP is :code:`SimpleReadout` with ``head_type: mlp`` and ``identity_residual: true``; :code:`AtomicAffine` is the elemental reference. :meth:`~enerzyme.models.dpa4c.blocks.DPA4CHead.fit_output_calibration` sets the fixed diagonal preconditioner from :meth:`~enerzyme.models.dpa4c.blocks.DPA4CBlock.raw_descriptor`. The default preconditioner is the identity. Further message-passing blocks, native spin, frame charge, and the compressed CUDA kernels are not in this Core. Example: :code:`enerzyme/config/dpa4c_layers_example.yaml`. Tests: :code:`test/test_dpa4c_ops.py`, :code:`test/test_dpa4c_core.py`. Enerzymette only needs :code:`architecture: dpa4c` plus a resolved :code:`config.yaml`.

**TACE** (:code:`architecture: tace`) is a native port of Xu et al. (arXiv:2509.14961; Cartesian-3j arXiv:2512.16882) under :code:`enerzyme/models/tace/` (:code:`interaction.py`), adapted from `xvzemin/tace <https://github.com/xvzemin/tace>`_ (MIT). Shared flat-Irreps helpers live in :code:`enerzyme/models/mp/equivariant/e3nn/`; radial MLPs use :code:`blocks.radial_mlp.RadialMLP`. The Core is the ACE message/product stack only (edge update + CgtpInteraction / Cartesian ICT + CgtpACE); embeddings, property heads, ZBL/LES/UIE stay outside. Switch backends with Core param :code:`tensor_basis: spherical|cartesian` (default spherical). TECE / SO2 / RRA live in the separate :code:`tece` architecture. Emits :code:`atom_feature` with :code:`feature_irreps` / :code:`dim_feature_out` for :code:`SimpleReadout`. Examples: :code:`enerzyme/config/tace_layers_example.yaml`, :code:`tace_cartesian_layers_example.yaml`. Tests: :code:`test/test_tace_core.py`, :code:`test/test_tace_spherical_ops.py`, :code:`test/test_tace_cartesian_ops.py`, :code:`test/test_tace_parity_ops.py`. Enerzymette only needs :code:`architecture: tace` plus a resolved :code:`config.yaml`.

**TECE** (:code:`architecture: tece`) is a native port of Xu et al. (arXiv:2607.10664) under :code:`enerzyme/models/tece/` (:code:`interaction.py`), adapted from the same `xvzemin/tace <https://github.com/xvzemin/tace>`_ v0.2.0 SO2 path (MIT). The Core runs a tensor seed (scalar → equivariant) then uvSO2 layers with **Edge Cluster Expansion** (:code:`ComplexProductBasis`) and **Radial Rotary Attention** (complex Q·K + radial phase), followed by node-side :code:`CgtpACE` reused from TACE. Shared SO(2) primitives (:code:`WignerD`, :code:`uvSO2Linear`, :code:`SO2Gate`, :code:`LayoutTransform`) live in :code:`enerzyme/models/mp/equivariant/`. Requires :code:`Lmax == lmax`. Distinct from EFA's Euclidean RoPE. Emits :code:`atom_feature` for :code:`SimpleReadout`. Example: :code:`enerzyme/config/tece_layers_example.yaml`. Tests: :code:`test/test_tece_core.py`, :code:`test/test_tece_ops.py`. Enerzymette only needs :code:`architecture: tece` plus a resolved :code:`config.yaml`.

**So3krates** (:code:`architecture: so3krates`) is a native port of Frank et al. (NeurIPS 2022) under :code:`enerzyme/models/so3krates/`, following the So3krates-torch EuclideanTransformer (fused FeatureBlock + GeometricBlock + InteractionBlock). Shared :code:`RealSphericalHarmonics` and :code:`L0Contraction` live in :code:`enerzyme/models/mp/equivariant/`. The Core emits :code:`atom_feature` (invariant stream ``x``, :code:`feature_irreps: "Fx0e"`) and :code:`atom_sphere_feature` (SPHC ``χ`` with shape ``[N, m_tot]``, **not** eSCN/EquiformerV2's ``[N, (lmax+1)^2, C]`` — :code:`SphereSampleReadout` does not apply). Default stacks use :code:`BernsteinRBF` + :code:`SimpleReadout` + :code:`EnergyReduce` + :code:`Force`. Long-range physics (ZBL / electrostatics / dispersion) belong in post-core layers, not inside the Core. Example: :code:`enerzyme/config/so3krates_layers_example.yaml`. Parity: :code:`test/test_so3krates_parity_ops.py`.

**SO3LR** (:code:`architecture: so3lr`) is a So3krates **variant** (Kabylda et al., JACS 2025): the same :code:`So3kratesCore` plus charge/spin embeds and shared physics layers configured for SO3LR — :code:`ZBLRepulsionEnergy` with :code:`switch_off: 1.5`, :code:`ElectrostaticEnergy` with :code:`flavor: SO3LR` (``erf(r/σ)/r``, pretrained ``σ=4``), and :code:`TSQDODispersionEnergy` (Hirshfeld-scaled TS + vdW-QDO; **not** Grimme D3/D4). Post-core heads: :code:`SimpleReadout(Qa)` + :code:`AtomicAffine` (unit scale; element shift), :code:`HirshfeldReadout` (``ha``). Defaults match the public pretrained hyperparams (``r_max=4.5``, ``L≤4``, ``H=128``, ``T=3``, phys cutoff). Example: :code:`enerzyme/config/so3lr_layers_example.yaml`. Tests: :code:`test/test_so3lr.py`. Enerzymette only needs :code:`architecture: so3lr` plus a resolved :code:`config.yaml`.

**Euclidean Fast Attention (EFA)** is a linear-scaling geometry-aware nonlocal plug-in (Frank et al., arXiv:2412.08541) implemented under :code:`enerzyme/models/efa/` (PyTorch; no JAX). Three wiring modes:

1. **SpookyNet** — set Core :code:`use_efa: true` to replace geometry-free :code:`NonlocalInteraction` with :code:`EFABlock` (needs absolute :code:`Ra`). Default remains :code:`false` for checkpoint compatibility.
2. **So3krates lineage** — :code:`architecture: efa` (So3krates + EFA) and :code:`architecture: so3lr_efa` (SO3LR stack + EFA). Both reuse :code:`So3kratesCore` with :code:`era_use_in_iterations` (e.g. ``[0, 1]``). EFA updates the **invariant** stream only; SPHC stays local.
3. **Other / future Cores** — call :code:`EFABlock` or :code:`apply_efa_if_configured` on invariant ``[N, F]`` features with :code:`Ra` and :code:`batch_seg` (see developer guide). Do not feed eSCN/EquiformerV2 ``atom_sphere_feature`` layouts into L=0 EFA.

Examples: :code:`enerzyme/config/efa_layers_example.yaml`, :code:`so3lr_efa_layers_example.yaml`. Tests: :code:`test/test_efa.py`.

**UMA** (:code:`architecture: uma_qs`) requires the :code:`fairchem` package. The Core wraps Meta's UMA / eSCN-MD backbone as an atom descriptor under :code:`enerzyme/models/esen/` (the package also holds native eSEN; this wrapper is **not** :code:`architecture: esen` and **not** the 2023 paper eSCN). Shared layers such as :code:`SimpleReadout`, :code:`HierachicalReadout`, and :code:`SpinConservation` predict atomic or molecular charge/spin outside the Core. Pair with :code:`aselmdb` datasets that provide :code:`Q` / :code:`S` (and optionally :code:`Qa` / :code:`Sa`).

.. warning::

   **AllScAIP** (:code:`architecture: AllScAIP`) in Enerzyme is an **experimental, heavily adapted (魔改)** port of fairchem-style attention IP, not a drop-in of the upstream model.
   It is **not recommended as a primary production architecture** yet. Prefer PhysNet, SpookyNet, MACE, or UMA for real campaigns; keep AllScAIP for research / ablation only (:code:`train.yaml` FF08 stays :code:`active: false` by default). The Core emits :code:`atom_feature` only — always attach :code:`SimpleReadout` (or NSE heads) before energy/charge physics layers.

For AllScAIP training that requires rotational invariance of the energy, set
:code:`equivariant_mode: true` on the Core. This selects the equivariant
input block and disables the direction-dependent attention mask. The default
input block has a different parameter layout.

Selection guidelines
--------------------

**Baseline / tutorial**
    SchNet — minimal dependencies, charge-aware stacks available.
    PaiNN — Cartesian scalar and vector features; energy from :code:`SimpleReadout`, dipole and polarizability from the shared tensor heads.
    REANN — invariant embedded-atom densities with recursive orbital coefficients. Charges and dipoles use the shared readout; polarizability is :code:`DerivativePolarizability`.
    EquiREANN — the same density, with the neighbor's Cartesian orbital passed at each coefficient update. The latent stays invariant, so the same readout and response heads apply.
    DimeNet — directional messages with Bessel RBF; invariant node states.
    DimeNet++ — same stack with the Hadamard bottleneck when the bilinear tensor is expensive.
    GemNet-T — directional triplets at the receiver, one cutoff, conservative forces.
    GemNet-Q — the same stack plus dihedral quadruplets on a longer interaction cutoff.
    SpinConv — edge messages on a source-centered sphere, pooled around the bond. Conservative forces.
    M3GNet — three-body bonds at the receiver plus a gated graph convolution. The graph cutoff is longer than the three-body cutoff.
    CHGNet — the same cutoff split on an explicit bond graph. The magnetic-moment magnitude is read from the latent before the last atom convolution.

**Production QM-labeled clusters with charge and solvent**
    PhysNet or SpookyNet — long-range electrostatics, optional dispersion layers.

**Maximum accuracy on diverse geometries**
    BOTNet, MACE, NequIP, Allegro, Nequix, EQNorm, Equiformer, EquiformerV2, EquiformerV3, E2Former, E2Former-V2, E2Former-LSR, So3krates, PaiNN, EquFlash, EquFlashV2, FACTO, GRACE, or Geodite — equivariant message passing; tune cutoff and depth.
    BOTNet is the body-ordered two-body convolution from the same design space as MACE (cutoff 4 Å, polynomial envelope order 6). MACE adds the symmetric product inside each layer.
    NequIP is the E(3) tensor-product convolution (cutoff 5 Å, 4 layers, :math:`\ell_{\max}=1`, 8 Bessel functions in the default stack). Chemical embedding and the energy head stay outside the Core.
    Allegro keeps that tensor product local to each center: layers raise body order without enlarging the cutoff, which is the stack to prefer when the system is large and a growing receptive field is unnecessary.
    Nequix is the simplified stack from Koker and Smidt: one-hot species, polynomial cutoff ``p = 6``, and RMSNorm. It is a separate Core from :code:`nequip`.
    EQNorm keeps a tensor state and a scalar accumulator (cutoff 6 Å, 4 layers, :math:`\ell_{\max}=3`, 8 trainable Bessel functions in the published stack). The one-hot species, the radial window, and the energy head stay outside the Core. With ``message_envelope: true``, Core ``polynomial_p`` stays 6 so the second window matches ``cutoff_fn: nequip``.
    FACTO keeps learned scalar and tensor state on the atoms (presets ``S`` through ``XL``).
    GRACE is the graph atomic cluster expansion (presets ``1L`` / ``2L`` and the Finnis–Sinclair student). Chemical embedding and the energy head stay outside the Core.
    Geodite-MP is SiLU attention and inner products (192 channels, 4 layers, :code:`lmax` 2, 6 Å, eV). The Bessel basis, covalent window, isolated-atom residual, bias-free readout, and screened ZBL stay outside the Core. :code:`lmax` stops at 4.
    PaiNN keeps equivariance in Cartesian vectors (cutoff 5 Å, 3 interactions, 20 Bessel functions in the paper) and is the path for dipole and polarizability spectra.
    ViSNet adds an edge state and runtime vector rejection on that same Cartesian pair (MD17: 9 layers, 8 heads, 256 channels, ``lmax`` 2, 5 Å). The dipole heads read the ``l = 1`` slice.
    QuinNet is the earlier quintuple stack on that same edge state (aspirin example: 5 layers, 8 heads, 256 channels, ``l = 2``, 5 Å). A learned ratio mixes the six body-order channels. The dipole heads read the ``l = 1`` slice.
    LEFTNet keeps equivariance in a local Cartesian frame (4 layers, 32 radial functions, 5 Å). Local substructure encoding and the frame transition stay in the Core. The species table, the ``exp(-r)`` basis, and the energy head stay outside.
    AlphaNet adds a rotary phase and a temporal matrix-product state on that frame (3 layers, 96 Bessel functions, 16 heads in the reference config). The default frame transition is the rotationally equivariant Euclidean norm.
    EquFlash keeps equivariance in an e3nn irrep stack (cutoff 6 Å, XPLOR from 5.5 Å, 10 convolutions, lmax 3, 8 Bessel functions in the released config).
    EquFlashV2 is the channelwise Clebsch–Gordan stack on that same Bessel / XPLOR window.
    Equiformer uses SO(3) graph attention (default MD17-style stack with ``ExpNormalSmearing``
    and :code:`output_mode: feature` emitting full irreps plus :code:`feature_irreps`;
    production default is :code:`SimpleReadout` with :code:`head_type: two_layer` after 0e
    extract, optional :code:`EquiformerGraphAttentionReadout`); prefer smaller irreps /
    fewer layers for enzyme-scale clusters. EquiformerV2 uses SO(2)-reduced attention
    (default :code:`GaussianRBF` with SchNet width / no RBF envelope + :code:`atom_feature` / :code:`atom_sphere_feature`)
    and scales more easily to higher :code:`lmax` with truncated :code:`mmax`.
    EquiformerV3 adds merged LN, SwiGLU-S², and smooth-cutoff attention on the same
    latent contract (default :code:`norm_type: merge_layer_norm`,
    :code:`attn/ffn_activation: sep-merge_gates2_swiglu`, :code:`use_envelope: true`).
    So3krates uses dual-stream geometric attention
    (invariants + SPHC; default :code:`BernsteinRBF` + :code:`architecture: so3krates`).
    Charge/dipole use shared readouts outside the Core. Numerical fidelity against the
    official Equiformer MD17 path is covered by :code:`test/test_equiformer_parity_*.py`
    (operator / latent / direct E·F / gradient checks — not the production SimpleReadout stack);
    EquiformerV2 ops/blocks by :code:`test/test_equiformer_v2_parity_*.py`;
    EquiformerV3 ops/blocks by :code:`test/test_equiformer_v3_parity_*.py`;
    E2Former Wigner-6j / SO2 TP by :code:`test/test_e2former_parity_ops.py`;
    TACE spherical / Cartesian by :code:`test/test_tace_parity_ops.py`;
    So3krates by :code:`test/test_so3krates_parity_ops.py`.

**Active learning with force variance**
    Any architecture with :code:`ShallowEnsembleReduce` or :code:`committee_size` > 1.

**Not for production yet**
    AllScAIP — experimental Enerzyme adaptation; see warning above.

Spin and charge
---------------

Charge-aware stacks need :code:`Q` (and often :code:`ChargeConservation`). SpookyNet-style models may use :code:`ElectronicEmbedding` for :code:`charge` and :code:`spin` (:code:`S` / multiplicity). Match simulation :code:`System.charge` and :code:`multiplicity` to training data conventions.

-----------------

NSE and flow matching
---------------------

Neural Spin Equilibration (:code:`NSEReadout` / :code:`NeuralSpinChargeEquilibration`) lives in shared layers outside Core. Existing architectures expose :code:`output_mode: feature` so Core emits :code:`atom_feature` for modular Q/S heads.

:code:`architecture: uma_flow_qs` uses continuous-flow charge/spin generation on top of the UMA Core. Install :code:`pip install -e ".[flow]"` for :code:`torchdiffeq`, plus fairchem. Example layer stacks: :code:`enerzyme/config/uma_qs_layers_example.yaml` and :code:`enerzyme/config/uma_flow_qs_layers_example.yaml`.
