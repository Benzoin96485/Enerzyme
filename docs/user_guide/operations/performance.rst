Performance Tuning
==================

Guidelines for large datasets and expensive simulations.

Data loading
------------

:code:`preload: true`
    Reuse HDF5 cache across runs with identical preprocessing hash.

:code:`compressed: true`
    Share static fields across frames of the same stoichiometry.

:code:`max_memory`
    Increase HDF5 cache (GB) for random-access heavy workloads.

:code:`num_workers`
    Dataloader parallelism; increase until CPU saturates; watch memory.

:code:`data_in_memory`
    Load full training set into RAM — fast but memory-intensive.

Training
--------

:code:`batch_size`
    Largest value that fits GPU memory.

:code:`dtype: float32`
    Default for speed; :code:`float64` for numerical experiments.

:code:`neighbor_list: full` (precomputed)
    Faster epochs if memory allows; otherwise on-the-fly lists.

:code:`lightning: true`
    Select the Lightning trainer. Native multi-GPU training uses PyTorch DDP.
    See :doc:`../workflows/distributed_training` for launch and batch-size settings.

Simulation
----------

:code:`dtype: float64` vs :code:`float32`
    Optimization and NEB often need :code:`float64`; MD may use :code:`float32` if stable.

:code:`cuda: true`
    GPU inference for ML calculator; external QC still runs on its own resources.

:code:`log_interval`
    Reduce trajectory I/O frequency for long MD.

Neighbor list memory
--------------------

Full neighbor lists scale as :math:`O(N^2)`. For large enzyme clusters:

- Use :code:`compressed` in training data
- Avoid storing redundant frames
- Consider smaller QM fragment training sets via extract/annotate rather than full-cluster every step

When to use server mode
-----------------------

:code:`listen` amortizes model load cost over hundreds of short requests (e.g. ORCA optimization loops). For one-off batch predict, use :code:`enerzyme predict`.


Comparing CUDA hardware
-----------------------

Run the baseline and candidate on the **same physical GPU** for each GPU model you want to evaluate.
The paired benchmark uses the active Python environment, two source checkouts, one frozen weight file
and identical coordinates. The repository includes trained SchNet, PhysNet, MACE and SpookyNet
fixtures in :file:`test/fixtures/main_legacy/`.

From the candidate checkout, run the following in an allocated GPU environment. Set
``CUDA_VISIBLE_DEVICES`` to select the intended card when the allocation exposes several GPUs.

.. code-block:: bash

   python scripts/bench_cuda_pair.py \
     --baseline /path/to/baseline-checkout --candidate . \
     --main-fixture test/fixtures/main_legacy/schnet_default.pt.gz \
     --systems bulk_256 --modes infer train --precision float32 \
     --execution eager --out results/schnet-periodic-eager.json

Use ``--execution compile`` for ordinary :func:`torch.compile` or ``--precision float64`` for double
precision. For other presets, supply a pre-refactor snapshot generated by
:file:`scripts/snapshot_cores.py` via ``--snapshot``. Omitting ``--systems`` covers the molecular batch,
256-atom periodic cell and 2000-atom cluster. Use ``--order ab`` for a shorter single comparison.
The default runs baseline, candidate, candidate, baseline in fresh processes. Each process warms up
twice and reports the median latency and peak allocated memory over five repetitions.

The JSON identifies the physical GPU UUID, compute capability, memory, CUDA runtime, PyTorch and
Triton versions, source revisions and fixture hash. Timings require matching energies, forces and
every active training-weight derivative across checkouts and against each checkout's native
reference. The default threshold is 3% for each time and memory comparison. The command returns
a nonzero status if any requested cell fails. Record a separate JSON on each target GPU. A
V100 measurement establishes its result on Volta; Ampere, Ada, Hopper and Blackwell timings
require measurements on the respective devices.

The model code chooses CUDA paths using the tensors' device, dtype and training or compilation
mode. E2Former's optional Triton QK and value kernels use the PyTorch path for FP64 and
:mod:`torch.func` transforms. Check the sparse-kernel numerical tests and a model with periodic
image offsets on the target card:

.. code-block:: bash

   python -m pytest -q test/test_e2former_triton_parity.py test/test_cuda_periodic_forces.py
